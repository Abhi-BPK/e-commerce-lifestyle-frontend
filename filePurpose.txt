========================================================
  FILE PURPOSE REFERENCE — E-Commerce Lifestyle Frontend
========================================================
This file documents the purpose of every source file in
the project, grouped by category. Use it as a map when
navigating the codebase.

--------------------------------------------------------
  ROOT CONFIG FILES
--------------------------------------------------------

package.json
  Declares all project dependencies (React 19, Redux
  Toolkit, Axios, React Router v7, Vite, etc.) and
  defines the npm scripts: dev, build, lint, preview.

package-lock.json
  Auto-generated by npm. Locks every dependency to an
  exact version so all developers get identical installs.
  Never edit this file by hand.

vite.config.js
  Configures Vite (the build tool). Sets up the React
  plugin so JSX is transpiled and enables fast Hot Module
  Replacement (HMR) during development.

eslint.config.js
  ESLint rules for code quality. Enforces React 19 best
  practices, catches common mistakes (unused variables,
  missing keys in lists), and keeps code style consistent
  across the team.

index.html
  The single HTML page the browser loads. Vite injects
  the compiled JS bundle here at build time. Contains the
  <div id="root"> that React mounts into.

.gitignore
  Tells Git which files to ignore (node_modules, dist,
  .env files, IDE config). Prevents secrets and generated
  files from being accidentally committed.

.env
  Stores environment-specific variables (e.g. API base
  URL). Loaded by Vite at build time. Never committed to
  version control — every developer keeps their own copy.

README.md
  Project overview and quick-start guide. Explains how
  to install dependencies and run the dev server.

CLAUDE.md
  Project guidelines for the Claude AI assistant. Tells
  Claude the tech stack, folder structure, coding rules,
  and React 19 conventions to follow in this project.
  Committed to Git so the whole team shares the same
  Claude behaviour.

CLAUDE.local.md
  Personal, gitignored Claude preferences. Used to store
  your own Claude settings that do not apply to the rest
  of the team (e.g. personal explanation preferences).

--------------------------------------------------------
  CLAUDE RULES  (.claude/rules/)
--------------------------------------------------------

.claude/settings.json
  Permissions file for the Claude AI harness. Controls
  what Claude is and is not allowed to do in this project
  (e.g. allow npm scripts, deny force-push). Committed to
  Git so the whole team has the same guardrails.

.claude/settings.local.json
  Personal, gitignored version of settings.json. Add
  permissions here that only you personally need — they
  will not affect other developers.

.claude/rules/components.md
  Tells Claude how to write React components in this
  project: destructure props, use default exports, keep
  components under 150 lines. Governs component-related
  work only, keeping the rule focused.

.claude/rules/testing.md
  Tells Claude the project testing conventions — which
  library to use, where test files live, what to test.
  Without this, Claude might write tests in a completely
  different style than expected.

.claude/rules/git.md
  Tells Claude the Git workflow — branch naming, commit
  message format, PR rules. Ensures Claude stays
  consistent with team conventions when helping with
  commits or branch names.

.claude/rules/hooks.md
  Guidelines for using React hooks in this project:
  when to write custom hooks, naming conventions, rules
  of hooks reminders.

.claude/rules/http-forms.md
  Rules for HTTP requests and form handling — use Axios
  with the shared instance, validate with React Hook
  Form, normalise errors via errorNormalizer.

.claude/rules/patterns-best-practices.md
  General coding patterns and best practices: feature
  folder structure, single responsibility, avoiding
  premature abstractions.

.claude/rules/routing-auth.md
  Routing and authentication conventions: how to add
  protected routes, how to read auth state, route path
  constants.

.claude/rules/state-management.md
  Redux Toolkit conventions: when to use Redux vs local
  state, slice structure, selector patterns.

--------------------------------------------------------
  PUBLIC ASSETS  (public/)
--------------------------------------------------------

public/favicon.svg
  The small icon shown in the browser tab. Served as a
  static file — not processed by Vite.

public/icons.svg
  An SVG sprite sheet. Holds multiple named icon shapes
  that can be referenced anywhere in the app with
  <use href="/icons.svg#icon-name">.

--------------------------------------------------------
  CORE APP  (src/)
--------------------------------------------------------

src/main.jsx
  The application entry point. Creates the React root
  with createRoot(), wraps the app in the Redux
  <Provider> and React Router, then calls render().
  Also sets up Axios interceptors and global error
  handlers on startup.

src/App.jsx
  The top-level React component. Renders the router
  outlet and any global wrappers (e.g. ErrorBoundary,
  AuthContext provider) that must surround the entire
  application.

src/App.css
  Styles scoped to the App component (layout, global
  font, body background). Imported only in App.jsx.

src/index.css
  Baseline global CSS reset — removes default browser
  margins, sets box-sizing, and defines font defaults
  applied to every element on the page.

src/styles/global.css
  Design-token variables (CSS custom properties for
  colours, spacing, border-radius, shadows) and utility
  classes used across all components.

--------------------------------------------------------
  API LAYER  (src/api/)
--------------------------------------------------------

src/api/axios.instance.js
  Creates and exports a single Axios instance configured
  with the API base URL (from .env) and a default
  timeout. All HTTP calls across the app import this
  shared instance so settings only need to change in
  one place.

src/api/interceptors.js
  Attaches request and response interceptors to the Axios
  instance. The request interceptor injects the auth
  token from Redux into every outgoing header. The
  response interceptor logs responses and triggers an
  automatic logout when the server returns 401
  (token expired / unauthorised).

src/api/errorNormalizer.js
  Converts every possible Axios error shape (network
  error, server error with a body, timeout, etc.) into
  one predictable object: { status, message, field,
  code }. Components can rely on this consistent shape
  instead of writing their own error-parsing logic.

--------------------------------------------------------
  REDUX STORE  (src/store/)
--------------------------------------------------------

src/store/store.js
  Configures and exports the Redux store using Redux
  Toolkit's configureStore(). Combines the auth and cart
  slice reducers so the whole app shares a single state
  tree.

src/store/slices/authSlice.js
  Manages authentication state: the JWT token and the
  current user object. Hydrates from localStorage on
  startup so users stay logged in after a page refresh.
  Exposes setCredentials and logout action creators.

src/store/slices/authSlice.test.js
  Unit tests for the auth slice. Verifies that
  setCredentials stores the token and user, that logout
  clears them, and that the slice hydrates correctly from
  localStorage.

src/store/slices/cartSlice.js
  Manages shopping cart state. Supports adding items,
  removing items, changing quantity, and clearing the
  entire cart. Uses optimistic updates — the UI changes
  immediately, before any server confirmation.

src/store/slices/cartSlice.test.js
  Unit tests for the cart slice. Covers add, remove,
  update-quantity, and clear-cart scenarios.

--------------------------------------------------------
  SHARED UTILITIES & HOOKS  (src/shared/)
--------------------------------------------------------

src/shared/utils/constants.js
  Central location for app-wide constants: route path
  strings (avoids typos in <Link to="...">), user role
  names, sort-option labels, tax rate, and the list of
  men's clothing subcategories.

src/shared/hooks/useLogger.js
  Custom hook that gives any component easy access to
  the centralised logger service. Components call
  logger.info() / logger.error() without importing the
  service directly.

src/shared/hooks/useNavigationGuard.js
  Blocks browser navigation (back button, link click)
  when the user has unsaved changes. Shows a
  confirmation dialog using React Router v7's
  useBlocker() hook to prevent accidental data loss.

--------------------------------------------------------
  SHARED COMPONENTS  (src/shared/components/)
--------------------------------------------------------

src/shared/components/Navbar.jsx
  The top navigation bar rendered on every authenticated
  page. Shows the brand logo, main category links, a
  cart icon with item-count badge, the user avatar, and
  a logout button. Uses sticky positioning so it stays
  visible while scrolling.

src/shared/components/Navbar.module.css
  CSS Module for the Navbar. Implements the
  frosted-glass background effect (backdrop-filter),
  responsive layout, and hover/active link styles.

src/shared/components/Navbar.test.jsx
  Tests for the Navbar component. Verifies that the
  cart badge shows the correct count and that the logout
  button dispatches the Redux logout action.

src/shared/components/ErrorBoundary.jsx
  A React class-based Error Boundary (the only place a
  class component is justified in React 19). Catches any
  unhandled render error in its child tree, displays a
  user-friendly fallback UI, and reports the error to
  the logger (Sentry-ready in production).

src/shared/components/ErrorBoundary.module.css
  Styles for the ErrorBoundary fallback screen: centred
  card, error icon, message text, and a retry button.

src/shared/components/Spinner.jsx
  A reusable loading spinner component. Rendered while
  async data is being fetched (products, orders, etc.)
  to give visual feedback to the user.

src/shared/components/Spinner.module.css
  CSS Module for the Spinner: CSS keyframe animation for
  the rotating ring, and size variant classes.

--------------------------------------------------------
  ROUTER  (src/router/)
--------------------------------------------------------

src/router/index.jsx
  Defines the entire client-side routing tree with React
  Router v7. Pages are lazy-loaded (dynamic import) for
  code splitting — the browser only downloads a page's
  JS when the user navigates to it. Wraps public routes
  in RootLayout and private routes in ProtectedLayout
  (redirects to /login if unauthenticated).

--------------------------------------------------------
  LOGGER SERVICE  (src/logger/)
--------------------------------------------------------

src/logger/logger.service.js
  Centralised logging utility. In development it writes
  to the browser console. The production build is wired
  to send logs to Sentry or Datadog (swap in the env
  variable). Using a single service means logging
  behaviour can be changed everywhere by editing one file.

--------------------------------------------------------
  FEATURE: AUTH  (src/features/auth/)
--------------------------------------------------------

src/features/auth/AuthContext.jsx
  React Context provider that exposes { user,
  isAuthenticated, logout } to any component in the
  tree. Reading auth state through context (rather than
  Redux directly) keeps UI components decoupled from the
  state management library.

src/features/auth/hooks/useLogin.js
  Custom hook for the login flow. Uses React 19's
  useActionState to manage the form's pending / error /
  success states in a single action function. On success
  it stores the token in Redux and redirects home.

src/features/auth/hooks/useSignup.js
  Custom hook for the signup flow. Same pattern as
  useLogin — wraps the signup service call in
  useActionState and handles validation errors returned
  from the API.

src/features/auth/components/LoginForm.jsx
  The controlled login form (email + password fields,
  submit button). Delegates all logic to the useLogin
  hook and shows inline validation / error messages.

src/features/auth/components/LoginForm.module.css
  Styles for LoginForm: card layout, input focus rings,
  error text colour, loading state for the submit button.

src/features/auth/components/LoginForm.test.jsx
  Tests for LoginForm. Covers: renders fields correctly,
  shows an error on bad credentials, disables the submit
  button while the request is pending.

src/features/auth/components/SignupForm.jsx
  The controlled signup form (name, email, password,
  confirm-password fields). Delegates all logic to
  the useSignup hook.

src/features/auth/components/SignupForm.module.css
  Styles for SignupForm, matching the LoginForm card
  style for visual consistency.

src/features/auth/pages/Login.jsx
  Page component for the /login route. Centres the
  LoginForm card on the screen and includes a link to
  the signup page.

src/features/auth/pages/Login.module.css
  Full-page layout styles for the Login page (centred
  flex container, background gradient).

src/features/auth/pages/Signup.jsx
  Page component for the /signup route. Centres the
  SignupForm card and links back to the login page.

src/features/auth/pages/Signup.module.css
  Full-page layout styles for the Signup page.

src/features/auth/services/auth.service.js
  Mock authentication service. Contains hardcoded demo
  user accounts and generates fake JWT tokens. Simulates
  network delay with setTimeout so loading states work
  realistically. Replace with real API calls when a
  backend is available.

--------------------------------------------------------
  FEATURE: CART  (src/features/cart/)
--------------------------------------------------------

src/features/cart/hooks/useCart.js
  Custom hook that reads cart state from Redux and
  exposes computed values (item count, subtotal) plus
  action dispatchers (addItem, removeItem,
  updateQuantity). Components never import Redux
  selectors directly — they use this hook instead.

src/features/cart/components/CartItem.jsx
  Renders a single row in the cart: product image,
  name, unit price, quantity stepper (+ / −), and a
  remove button. Calls the useCart dispatchers on
  user interaction.

src/features/cart/components/CartItem.module.css
  Styles for the CartItem row: flexbox layout, quantity
  button styles, hover state for the remove button.

src/features/cart/components/CartItem.test.jsx
  Tests for CartItem. Verifies quantity controls fire
  the correct Redux actions and the remove button works.

src/features/cart/components/CartSummary.jsx
  The order summary sidebar. Displays subtotal, tax
  (calculated from the constant tax rate), grand total,
  and a "Proceed to Checkout" button.

src/features/cart/components/CartSummary.module.css
  Styles for the CartSummary card: border, spacing,
  grand total line emphasis, and checkout button style.

src/features/cart/components/CartSummary.test.jsx
  Tests for CartSummary. Checks that subtotal, tax, and
  total are calculated and displayed correctly.

src/features/cart/pages/Cart.jsx
  The /cart page. Two-column layout: CartItem list on
  the left, CartSummary on the right. Shows an empty
  state with a "Continue Shopping" link when the cart
  has no items.

src/features/cart/pages/Cart.module.css
  CSS Module for the Cart page: responsive two-column
  grid that stacks into a single column on mobile.

--------------------------------------------------------
  FEATURE: CHECKOUT  (src/features/checkout/)
--------------------------------------------------------

src/features/checkout/hooks/useCheckout.js
  Thin wrapper that re-exports the usePlaceOrder hook.
  Keeps CheckoutForm decoupled from the orders feature —
  it imports from checkout, not orders directly.

src/features/checkout/components/CheckoutForm.jsx
  The checkout form. Collects shipping address fields
  (name, street, city, postcode, country). Submits via
  the usePlaceOrder hook and shows loading / error states.

src/features/checkout/components/CheckoutForm.module.css
  Styles for CheckoutForm: form grid layout, input focus
  rings, submit button, inline field error messages.

src/features/checkout/pages/Checkout.jsx
  The /checkout page. Two-column layout: CheckoutForm on
  the left, CartSummary on the right. Redirects back to
  /cart if the cart is empty when the page loads.

src/features/checkout/pages/Checkout.module.css
  CSS Module for the Checkout page layout (same
  responsive two-column grid as the Cart page).

--------------------------------------------------------
  FEATURE: ORDERS  (src/features/orders/)
--------------------------------------------------------

src/features/orders/hooks/usePlaceOrder.js
  Handles order submission. Builds the order payload
  from cart items + shipping address, calls the orders
  service, clears the Redux cart on success, and
  navigates the user to the new order's detail page.

src/features/orders/hooks/useOrderHistory.js
  Fetches the list of past orders for the logged-in
  user. Manages loading and error states with useState
  and useEffect. Returns { orders, loading, error }.

src/features/orders/components/OrderCard.jsx
  A summary card for one order in the history list.
  Shows order ID, date, item count, total price, and an
  OrderStatus badge. Links to the order detail page.

src/features/orders/components/OrderCard.module.css
  Styles for the OrderCard: card border, flex layout,
  hover shadow effect.

src/features/orders/components/OrderCard.test.jsx
  Tests for OrderCard. Checks that order data renders
  correctly and the detail link points to the right URL.

src/features/orders/components/OrderStatus.jsx
  A small badge component that colour-codes an order
  status string (e.g. "Processing" → yellow,
  "Delivered" → green, "Cancelled" → red).

src/features/orders/components/OrderStatus.module.css
  CSS Module for the OrderStatus badge: background
  colours per status and typography styles.

src/features/orders/pages/OrderHistory.jsx
  The /orders page. Fetches all past orders via
  useOrderHistory and renders an OrderCard for each.
  Shows a loading spinner while fetching and an empty
  state if no orders exist yet.

src/features/orders/pages/OrderHistory.module.css
  Styles for the OrderHistory page: page title and
  card list spacing.

src/features/orders/pages/OrderDetail.jsx
  The /orders/:id page. Fetches a single order by ID
  and displays the full breakdown: line items, shipping
  address, order status, and total.

src/features/orders/pages/OrderDetail.module.css
  Styles for the OrderDetail page: section headings,
  line-item table, and summary totals layout.

src/features/orders/services/orders.service.js
  Mock orders service. Simulates placing an order and
  retrieving order history with setTimeout delays.
  Returns data from the mock dataset. Swap with real
  Axios calls when a backend is available.

src/features/orders/data/mockOrders.js
  Hard-coded array of sample order objects used by the
  mock orders service during development and testing.

--------------------------------------------------------
  FEATURE: MEN'S CLOTHING  (src/features/men/)
--------------------------------------------------------

src/features/men/data/menCategories.js
  Defines the men's clothing subcategories (party-wear,
  ethnic-wear, formal, casual, etc.). Each entry has a
  slug, a display label, and a cover image URL for the
  landing page grid.

src/features/men/data/menProducts.js
  Hard-coded array of sample men's clothing products.
  Each product has id, name, price, image, subcategory
  slug, and stock count. Used as the data source until
  a real products API is integrated.

src/features/men/hooks/useMenProducts.js
  Fetches (or reads) the men's product list, then
  filters by subcategory slug and applies the selected
  sort order (price, name, newest). Returns { products,
  loading, error }.

src/features/men/components/MenProductCard.jsx
  A product card used in the product listing grid.
  Shows the product image, name, price, and an
  "Add to Cart" button. Dispatches addItem to the
  Redux cart slice on button click.

src/features/men/components/MenProductCard.module.css
  Styles for MenProductCard: card shadow, image aspect
  ratio, hover lift effect, and price colour.

src/features/men/components/SubcategoryCard.jsx
  A card used on the Men's landing page for each
  subcategory (e.g. Formal, Casual). Shows the cover
  image and label, and links to the filtered product
  listing page.

src/features/men/components/SubcategoryCard.module.css
  Styles for SubcategoryCard: background image fill,
  overlay gradient, and label positioning.

src/features/men/pages/MenCategoryLanding.jsx
  The /men route. Hero banner at the top followed by a
  3-column grid of SubcategoryCards. Entry point into
  the men's clothing section.

src/features/men/pages/MenCategoryLanding.module.css
  Styles for the MenCategoryLanding page: hero
  dimensions, subcategory grid layout, and responsive
  breakpoints.

src/features/men/pages/MenProductListing.jsx
  The /men/:subcategory route. Reads the subcategory
  slug from the URL, passes it to useMenProducts, and
  renders a grid of MenProductCards. Includes a sort
  dropdown and a search input.

src/features/men/pages/MenProductListing.module.css
  Styles for the MenProductListing page: toolbar
  (sort + search) layout, product grid columns, and
  loading / empty-state messages.

src/features/men/pages/MenProductDetail.jsx
  The /men/:subcategory/:productId route. Displays the
  full detail view of a single product: large image,
  name, price, description, size selector, and an
  "Add to Cart" button.

src/features/men/pages/MenProductDetail.module.css
  Styles for MenProductDetail: two-column layout (image
  left, info right), size-selector pills, and responsive
  stacking on mobile.

src/features/dashboard/pages/Dashboard.jsx
  The /dashboard route — the home page after login.

src/features/dashboard/pages/Dashboard.module.css

--------------------------------------------------------
  TESTS  (src/test/)
--------------------------------------------------------

src/test/setup.js
  Vitest global setup file. Imports @testing-library/
  jest-dom so custom matchers like toBeInTheDocument()
  are available in every test file without having to
  import them individually each time.

src/test/testUtils.jsx
  Exports a custom render() wrapper that automatically
  surrounds every rendered component with the Redux
  <Provider> and the Router. Tests import this render
  instead of RTL's default so they do not need to set
  up providers themselves in every test file.
